# HooSharper code-fix review — November 17, 2026

The review started at `5a63cfb`. All 557 existing tests passed. The failures

## Reproduced failures

| Rules | What the old fix did | What changed |
| --- | --- | --- |
| HOO1001, HOO1004, HOO1010 | Moving a declaration next to an earlier LINQ query could turn valid code into CS1931. An unused range variable still reserves its name. | Check names declared by query clauses, including `let` and `into`, before widening a declaration's scope. |
| HOO1002 | Removing braces from an inner `else` let an outer `else` bind to a different `if`. A two-call branch probe changed from 30 to 3. | Keep the braces that determine which branch owns an `else`, including when Fix All can remove a neighboring block. |
| HOO1003, HOO1008, HOO1018 | Moving an `out var` outside a branch changed a later field read from 42 to 7 or produced CS0165. | Preserve the embedded `else` statement's scope; skip null-guard rewrites that would introduce a conflicting variable. |
| HOO1005 | A type alias named `var` changed overload selection from a wrapper to `string`. Rewriting `null as string` produced CS8117. A generic `as` test produced CS8314 under C# 7.0. | Verify the local's actual type, the pattern input type, and the conversions supported by the project's language version. The generic case remains eligible on C# 7.1. |
| HOO1006, HOO1019 | Removing a boolean comparison selected a different overload or made a call with `default` ambiguous. An `is not` fix under another `!` produced CS0023; under a cast it changed an `object` overload to `bool`. | Preserve boolean conversions and grouping. Skip a simplification if the operand needs the original comparison to supply its type. |
| HOO1007 | An unrelated static field initializer updated a dictionary between `ContainsKey` and the indexer. Taking the value earlier changed the result from 51 to 11. A type alias named `var` also made the generated `out var` invalid. | Check for static initialization before caching a read, and require `var` to be available for type inference. The analyzer and fixer use the same lookup checks. |
| HOO1008, HOO1014 | Replacing an assignment with `??=` could turn null into zero, including in target-typed conditionals. Both `??=` and `??` could choose a different conversion operator (42 became 13). Rewriting a ref reassignment produced invalid syntax. | Check nullable and underlying conversions before offering these rewrites. Leave ref reassignments in place. |
| HOO1009 | A local named `ArgumentNullException` could receive the generated method call. The original null guard threw; the rewritten method returned normally. | Check which method the emitted call binds to and qualify the framework type when needed. |
| HOO1008, HOO1009, HOO1010, HOO1018 | Comments on an assignment operator, a retained inner statement, or a removed closing brace could disappear or merge into another line comment. | Preserve operator trivia and retain both inner and outer trailing comments. |

The smoke tool now reparses each changed document after every project Fix All.
It uses the document's parse options before checking compiler diagnostics or
running the next rule. This catches grouping errors that a fixer's constructed
syntax tree can hide.
