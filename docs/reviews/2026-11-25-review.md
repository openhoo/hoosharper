# Real-project review — November 25, 2026

This review started from HooSharper 0.3.13 (`87c9949`). We ran native ReSharper
InspectCode on four pinned C# libraries, inspected differences in the source,
and tested HooSharper's fixes on the rewritten libraries. The changes retain
all 20 shipped diagnostic IDs, their default severities, and the package version.

## Fixes that affected user code

| Case | Reproduction and correction |
| --- | --- |
| Compiler-captured argument text | Removing braces around a call changed the string recorded by `CallerArgumentExpression` from `ready    ==      true` to `ready == true`. The analyzers now protect both captured syntax and whitespace in a subtree a fix would format. The executable probe preserved both captured strings byte for byte and still simplified an unrelated comparison. |
| Expression trees | A custom query provider can take an expression-tree selector without returning `IQueryable`. Conversely, a method returning `IQueryable` can accept a delegate. Five expression rules now inspect the bound lambda conversion. Tests cover both cases, so providers retain their original tree and ordinary delegates remain eligible. |
| Null assignment (HOO1008) | Newtonsoft.Json uses nonvirtual auto-properties on stable receivers. FluentValidation initializes `DependentRules` with a single unbraced assignment. Both are eligible for `??=`. Tests also cover different receivers, custom accessors, comments, and an `out var` that would shadow a field after lifting the assignment. |
| Argument null guards (HOO1009) | FluentValidation passed the literal `"info"` to `ArgumentNullException`. The rule accepts an exact literal for the checked parameter, preserves the exception's parameter name, and rechecks the source before applying a stale fix. |
| Nested conditions (HOO1010) | Removing braces could leave an otherwise mergeable pair of conditions behind. Braced, unbraced, and mixed chains now merge with the same short-circuit order. An ineligible outer condition using custom boolean operators no longer hides eligible inner conditions. |
| Boolean returns (HOO1017) | ReSharper found opposite returns in the same switch section in Newtonsoft.Json's `ReflectionUtils.cs:629`. HooSharper now handles that form, preserves trailing comments, and keeps returns in separate sections independent. |
| Indentation | In FluentValidation, removing braces or merging guards could double the indentation of an untouched neighboring line. Its EditorConfig specifies `indent_size = tab` and `tab_width = 2`. Formatted fixes now honor that width; the real rewritten files and focused regressions check the result. |
| Brace removal in Fix All (HOO1002) | Four runs on the same FluentValidation checkout produced three different final source trees. Overlapping brace-removal edits could leave different forms of a loop in `MemberNameValidatorSelector.cs`. Fix All now applies those edits together in one syntax tree per document. Four fresh runs agreed byte for byte on all 136 files; each removed all 179 initial brace findings in the first HOO1002 pass. |
| NuGet installation | Packing the analyzer from a clean checkout could omit the fixer build or look for it in the wrong directory. Direct pack now restores and builds the fixer and honors custom artifact paths. The consumer test installs the exact archive and runs its fix through `dotnet format analyzers`. |

## Native comparison and Fix All

The reference was JetBrains.ReSharper.GlobalTools **2026.2.3.1**. The development
SDK was **10.0.109**. Each library was analyzed with InspectCode on the modern
target; the .NET Standard 2.0 column is a separate HooSharper run. Arrows show
outstanding HooSharper findings before the first and after the last Fix All.

| Library | Modern target | HooSharper, modern | HooSharper, .NET Standard 2.0 | Native findings, modern | Mapped HooSharper findings that overlap native |
| --- | --- | ---: | ---: | ---: | ---: |
| Dapper 2.1.66 | .NET 8 | 294 → 0 | 266 → 0 | 1,348 | 262 / 288 |
| Newtonsoft.Json 13.0.3 | .NET 6 | 3,103 → 0 | 3,050 → 0 | 7,987 | 2,854 / 3,034 |
| Serilog 4.0.0 | .NET 8 | 121 → 0 | 93 → 0 | 1,058 | 99 / 119 |
| FluentValidation 11.11.0 | .NET 8 | 237 → 0 | 218 → 0 | 1,180 | 207 / 225 |

Across the four libraries, Fix All cleared 3,755 findings on the modern targets
and 3,627 on .NET Standard 2.0. It took at most three rounds. On Newtonsoft.Json
alone, one HOO1002 Fix All cleared all 2,641 brace findings.

Native totals include every enabled native inspection in the capture. They
exclude diagnostics from Roslyn analyzers loaded by ReSharper. Seventeen of
HooSharper's rules have a mapping; HOO1010, HOO1016, and HOO1020 have none in
this catalog. The comparison records inclusive line overlaps. A match locates
a candidate for source review; it does not mean the two quick fixes emit the
same code. One native inspection can also map to two HooSharper rules.

The following are native opportunities where a mapped HooSharper finding lands
on the same lines. The denominator is the number of native opportunities for
that rule, so it differs from the denominator in the project table.

| Library | Rule | Before this review | After |
| --- | --- | ---: | ---: |
| Newtonsoft.Json | HOO1008, use `??=` | 45 / 63 | 59 / 63 |
| Newtonsoft.Json | HOO1017, simplify boolean return | 12 / 129 | 13 / 129 |
| FluentValidation | HOO1008, use `??=` | 1 / 5 | 3 / 5 |
| FluentValidation | HOO1009, use `ThrowIfNull` | 18 / 22 | 19 / 22 |

Some differences are intentional. ReSharper's brace inspection covers loops;
HOO1002 covers `if` branches. Its conditional-return inspection also handles
arbitrary return values; HOO1017 requires opposite boolean literals. HOO1008
leaves custom and interface accessors alone; HOO1009 leaves overloaded
equality operators alone. For example, the remaining native null-assignment
sites on Newtonsoft.Json's `ItemContract` use a handwritten setter that also
updates `_finalItemContract`. The remaining FluentValidation null guards use
`System.Type` equality.

## Behavior on rebuilt code

| Pinned project | Library files rewritten | Original outcome | Outcome after Fix All |
| --- | ---: | --- | --- |
| Dapper 2.1.66 (`bd4f75b5`) | 20 | 12 upstream tests passed; reader probe: `123:abc;456:<NULL>` | Same 12 passed; identical probe output |
| Newtonsoft.Json 13.0.3 (`0a2e291c`) | 136 | 3,488 passed, 10 failed | Same 3,498 outcomes and exact messages for all 10 failures |
| Serilog 4.0.0 (`573a6287`) | 28 | 785 passed | 785 passed |
| FluentValidation 11.11.0 (`c8c6400f`) | 45 | 927 passed, 1 benchmark skipped | 927 passed, same benchmark skipped |
| DScaf (`14650181`) | 14 | 701 passed | 701 passed |

For Serilog, FluentValidation, Newtonsoft.Json, and the selected Dapper tests
we compared every test name and outcome, including multiplicity, and checked
the library DLL used by each test run. Dapper's upstream tests exercised
SQLite and DuckDB in memory, plus disposal of wrapped readers. The separate
[standalone probe](../../tests/smoke/DapperReader/README.md) checked typed
and untyped row parsers, parser reuse, column mapping, and `DBNull`. Dapper's
external database suites were not run. DScaf exercised the packaged fixer on
a fifth real project; it was not part of the native comparison.

For all four libraries, the runtime tests covered the source exported by the
modern native-comparison run. Dapper, Serilog, and FluentValidation also
produced the same final files in two independent runs per library.

Newtonsoft.Json produced different rewrites in two files under its Debug and
Release compiler settings. We tested both sets on .NET 6.0.36, macOS arm64:
3,107 → 5 → 1 → 0 findings under Debug, and 3,103 → 5 → 1 → 0 under Release.
For the Release run, the test process verified the SHA-256 of its loaded
library. All 233 tested source files matched the export byte for byte. The
smoke tool writes a normalized UTF-8 snapshot without byte-order marks, so
the table counts files with changed C# text; 68 additional files differed
only by their preamble in this exact replay.

On DScaf we promoted all HOO diagnostics to errors. Five HOO1002 findings,
one HOO1004, and 32 HOO1020 findings were reported. One `dotnet format` pass
with the local package removed all 38; Release then rebuilt with zero warnings
and zero errors on SDK 10.0.401.

## Verification and reproduction

- Release build: zero warnings and errors. All **618 tests passed** (579 at
  baseline); line coverage was **94.26%** (4,271 of 4,531; CI minimum 91%).
- Executable matrix: independent project Fix Alls compiled for all 20 rules.
  Cumulative Fix All reduced 44 findings to zero in one round; the original
  and rewritten programs produced byte-identical output.
- All 11 Python comparison/validation tests passed, as did 16 analyzer and
  16 code-fix benchmark workloads. The latter exercise correctness, not timing.
- The verified local package ran on SDKs **8.0.100** and **10.0.109**. Both
  applied HOO1006 and passed separate real-formatter checks for HOO1002 and
  HOO1010 with CRLF and two-column tabs. The resulting source matched the
  expected bytes on each host.
